# 作者个人技术偏好

这是 `pro-stack` 使用的技术偏好入口，来自作者个人的技术倾向。先读本文件的使用原则与路线索引，再按项目涉及的路线读取对应文件；按其中的条件提出建议，最终选择仍需结合项目需求。

## 使用原则

- 偏好按场景生效，需求与项目已确认架构优先。已有项目不因这份清单而自动升级或迁移。
- 开始新技术路线前先提出建议并协商；已经明确的决定无需再次确认。
- 只引入当前功能需要的组件。性能、美观、实现成本和维护成本共同影响选型。
- 各表的版本是作者提出的目标倾向，未在此声明发布状态或兼容性。实际选型时重新核对，保留偏好的技术与主版本方向，采用所选框架、SDK 与依赖共同支持的稳定版本并锁定依赖；移动端遵循所选 Expo SDK 等平台的兼容组合，不直接套用 Web 项目的版本要求。不能满足条件时说明偏离原因。
- 候选按路线分组。Web 与 React 路线中的组件、状态与交互库只用于 React 界面；Flutter 路线的组件与平台能力只用于 Flutter 界面，其状态管理与路由按需求另行选择；MyGo 原生 UI 等其他客户端路线的状态、路由与组件同样另行选择，各路线条目不互相套用。
- “适用条件与例外”用于防止机械套用；没有替作者新增未表达的框架优先级。
- 每个路线文件同时记录技术候选与官方入口，新增或调整候选时在同一文件内同步两张表；新增路线或子路线时，只在上一级文件的索引中登记。
- 官方入口只记录链接，不复制文档内容；版本、API 与兼容性以入口指向的当前文档为准，按 [选型流程](../SKILL.md) 的核验要求读取。优先使用宿主可用的文档工具检索对应库，需要直接打开页面时再从入口表进入。
