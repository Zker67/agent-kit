# 作者个人技术偏好

这是 `pro-stack` 使用的技术偏好，来自作者个人的技术倾向。按下述条件提出建议，最终选择仍需结合项目需求。

## 使用原则

- 偏好按场景生效，需求与项目已确认架构优先。已有项目不因这份清单而自动升级或迁移。
- 开始新技术路线前先提出建议并协商；已经明确的决定无需再次确认。
- 只引入当前功能需要的组件。性能、美观、实现成本和维护成本共同影响选型。
- 下表的版本是作者提出的目标倾向，未在此声明发布状态或兼容性。实际选型时重新核对；不能满足条件时说明偏离原因。
- “适用条件与例外”用于防止机械套用；没有替作者新增未表达的框架优先级。
- 各项候选的官网与文档入口见 [官方入口索引](./docs.md)，按下表同名领域查找；新增或调整候选时同步更新该索引。

## GPUI 路线的明确偏好

> 当标准化、精致的原生 UI 足够满足产品需求时，优先评估 GPUI + GPUI Kit 这条高性能技术路线。

适用倾向：桌面应用以基础功能和标准交互为主，对运行效率、资源占用或响应速度有较高要求；标准组件与布局能够满足需求，不需要特别风格化的视觉设计。

“不需要特别风格化”仍要求美观、精致和良好的交互体验，不意味着界面可以简陋。性能优先也不意味着仅凭框架名称认定更快。

选型时需确认：

- 目标平台支持，尤其是 Windows 上所需功能与交付方式。
- 组件覆盖、输入交互、系统集成、无障碍与打包要求。
- Rust 实现与维护成本，以及实际的性能证据。
- 是否需要复用已有 Web UI；采用原生 UI 路线时，重新评估 UI 与状态实现，不假定可以直接沿用 Web 组件。

这些条件不足时，比较 Tauri / Electron 或其他符合需求的路线，说明取舍，不盲目选择 GPUI。
