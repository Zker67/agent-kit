# Pro Notify

**由用户主动触发，不由 AI 自行决定通知。** 配好渠道不等于授权发送；点名但未说明用途时，先区分配置、立即发送、启用本次任务通知。只有第三种授权延续到当前任务的状态变化，不跨会话继承。

## 边界

- 支持飞书 / Lark、钉钉、企业微信的**群机器人 Webhook**，不是应用机器人、个人微信或私信接口。
- 第一版所有渠道只发纯文本，不发 Markdown、富文本、卡片、附件，不主动 `@all` 或增加接收者。
- “配置通知”只配置，不顺手发测试消息；“检查配置”只运行 `list` / `--dry-run`。
- 任务正常完成、遇到错误、需要提问，不会单独触发本 skill。用户只说“任务完成了”也不发送。
- 用户明确要求本次任务通知后，按实际发生的 `completed`、`failed`、`needs-input` 发送，同一任务、同一机器人、同一事件最多尝试一次（本地去重窗口 24 小时）。不是一激活就把三条都发出去。
- 不修改宿主 hooks、全局 instructions、调度器或常驻服务。Skill 无法保证模型中断、上下文丢失或进程退出后仍能通知。
- 宿主若要求优先使用已有 MCP / Connectors，遵循该路由，不绕过权限；只有本机脚本路线才由随附 CLI 管理凭据、去重和限流。其他路线也要维持相同的授权、纯文本和防刷屏边界。

## 一、确认本次动作

确定以下信息，已有明确答案就不重复问：

1. **动作**：配置 / 立即发送 / 启用本次任务的状态通知。
2. **目标**：一个或多个渠道别名。同一平台可有多个群，例如 `work`、`alerts`；平台名不是群的唯一标识。
3. **内容**：立即发送时按用户原文或授权摘要发送，不擅加代码、对话全文、日志、文件内容或敏感信息。
4. **事件**：默认立即发送为 `manual`。任务通知分配一个不含个人信息的稳定 `task-id`，三类事件沿用它。`needs-input` 发完仍在当前对话中提问，不阻塞等待群聊回复。

没有目标且存在多个已配置渠道时询问；不要默认广播到全部渠道。仅一个渠道时可用于“给我发通知”这种未限定平台的请求；若用户指定了其他平台，仍需匹配或新配置，不能悄悄改投。

## 二、定位与配置

先定位**本 skill 安装目录**下的 [scripts/notify.py](scripts/notify.py)，使用绝对路径执行。下面的 `<skill-dir>` 指该安装目录，绝不是假定当前业务仓库包含 `skills/`。需要 Python 3.10+；Windows 可用 `py -3`，其他环境通常为 `python3`。

```bash
python "<skill-dir>/scripts/notify.py" list
```

- 默认配置在 `~/.config/pro-notify/config.json`，与宿主、工作目录和 skill 重装分离；配置只保存别名、平台和凭据引用。
- 缺配置时由 AI 按用户选择调用 `configure`，不要求用户手写 JSON。
- 默认把用户已经安全提供的环境变量值导入**系统凭据库**，后续发送不需要原环境变量；需要可选依赖 `keyring` 及可用的系统凭据库。安装依赖前遵守宿主授权要求。
- 无凭据库（例如无桌面的 Linux / CI）时可显式选 `--store env`，只保存环境变量名，每次运行由宿主注入。不能偷偷降级为明文保存。
- 不让用户在聊天中贴真实凭据；不把值拼进命令行、版本库、skill 目录、日志或截图。用户已贴出的也不回显，建议轮换。只读取用户指定的凭据来源，不扫描全机配置找密钥。
- 具体配置命令、系统凭据库准备和用户安全输入方法见 [references/configuration.md](references/configuration.md)。

## 三、准备与发送

1. 根据 `list` 返回的别名和平台选目标。不要直接读取或打印凭据库；`list` 不验证凭据，`--dry-run` 才检查当前可用性。
2. 内容保持纯文本、简短、可执行。任务通知可写“任务：…；状态：…；结果 / 需要你处理：…”。所有渠道统一限制为 **2048 UTF-8 字节**，不自动截断或分片；超限先缩成授权范围内的摘要。
3. 通过标准输入或用户批准的 UTF-8 文本文件传消息，避免引号、反引号或换行被 shell 解释。敏感正文优先标准输入；不为发送擅自落盘。
4. 可先 `--dry-run`，它只校验目标、凭据、文本，不联网，不写去重状态、不发通知。真实发送去掉此参数。检查通过不代表群机器人接受过消息。
5. 同一次调用可重复 `--channel` 指定多个目标。CLI 先预检全部目标；预检失败则全部不发送。正式发送时逐渠道返回结果，一个渠道的服务端失败不影响其他渠道。

```bash
# 文件路径替换成用户批准的 UTF-8 消息文件；同一命令可选择多个渠道
python "<skill-dir>/scripts/notify.py" send --channel work --channel alerts --message-file "<message-file>" --dry-run
python "<skill-dir>/scripts/notify.py" send --channel work --message-file "<message-file>"

# 仅在用户明确启用了本次任务通知时；复用同一个 task-id
python "<skill-dir>/scripts/notify.py" send --channel work --event completed --task-id task-001 --message-file "<message-file>"
```

PowerShell 标准输入示例（UTF-8）：

```powershell
$OutputEncoding = [System.Text.UTF8Encoding]::new()
'本次任务已完成，检查通过。' | py -3 -X utf8 "<skill-dir>/scripts/notify.py" send --channel work --message-stdin
```

也可以从 Python 导入脚本调用 `configure(...)` 和 `send(...)`，示例见配置参考。不临时重写 HTTP 调用，以免绕开安全输出、签名、限流和服务端结果校验。

## 四、发送结果与防刷屏

| 结果 | 含义与动作 |
|---|---|
| `accepted` | 服务端已确认接受；不等于用户已读。 |
| `dry_run` | 仅本地检查通过，未发送。 |
| `duplicate` | 同任务、同机器人、同事件已有尝试，未重发；查看 `previous_status`，不能一概称成功。 |
| `rate_limited` | 本地滚动 60 秒已预留 20 次请求，未发送，不自动排队。 |
| `failed` | 服务端拒绝或本地状态不可用；报告失败，不附服务端原文。 |
| `unconfirmed` | 超时、断连或无法解释服务端响应，可能已经发出；禁止盲目重试。 |

- 三个平台均按每个机器人、滚动 60 秒最多 **20 次请求尝试** 保守限流，失败也计数。多进程使用文件锁预留额度，同一 Webhook 的多个别名共享额度。
- 状态在 `~/.config/pro-notify/state.json`，只含目标 / 事件摘要、时间和状态，不含正文或真实地址；跨工作目录和配置文件共用。只管同一机器、同一用户、使用该脚本的请求，不能约束其他工具、其他机器或平台自身限额。
- 无自动重试、自动补发、后台重发或通过备用渠道转发。用户要重试时先报告已确认成功的渠道，仅重试明确指定的失败目标；新事件 ID 或 `manual` 也必须有新的发送授权。
- `state_locked` 表示锁被占用。确认没有运行中的配置 / 发送进程后，再由用户决定是否清理对应 `.lock`；不要自动删锁，也不要删状态来绕过去重。
- 不把“发通知失败”再递归当作业务失败通知。

## 五、收尾

只报告目标别名、平台、已接受 / 未发送 / 失败 / 未确认，以及必要的下一步。不要回显 Webhook、签名、完整服务端响应或重复贴出正文。
