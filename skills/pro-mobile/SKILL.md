# Pro Mobile

教 AI 在需要手机时选对路线、连上设备、守住边界。选定路线后，按对应的参考文档操作；这些文档已经把安装、配置和用法核实过，照做即可，不必重新探索。

## 选路

| 场景 | 路线 | 按需读取 |
|---|---|---|
| 会话中已有 `mobile_*` 工具 | **mobile-mcp** | [mobile-mcp 用法](./references/mcp-usage.md) |
| 手机项目还没配置 mobile-mcp，需要反复操作界面、读元素、走流程 | **推荐项目级安装 mobile-mcp 与 mobile-automation skill** | [项目级安装](./references/mcp-setup.md) |
| 用户不想装 MCP、宿主没有项目级 MCP 配置，或只需一两条命令（装包、看日志、截一张图、`adb reverse` 映射开发服务器） | **adb / xcrun simctl 命令** | [命令路线](./references/adb.md) |
| 设备没连上、无线调试断开、找不到设备 | 先连接设备 | [连接设备](./references/connect.md) |
| 只看网页在窄屏下的布局 | 不用本 skill | 交给浏览器路线；只有真机特有的问题（触摸、键盘、系统浏览器差异）才转回来 |

判断顺序：

1. 会话里有 `mobile_*` 工具就直接用；项目里装有 `mobile-automation` skill 时一并遵循。
2. 没有时，当前项目是手机项目且需要多步界面操作，就向用户推荐项目级安装：MCP 配置和 `mobile-automation` skill 一起装，取仓库最新版本且两者版本一致。说明会在项目里新增或修改哪些文件、使用哪个版本、需要新开会话才会加载。用户同意后再写入；不写入用户级或全局配置，除非用户明确要求。
3. 用户不想装，或配置后要等新会话才能用，就走命令路线完成当前任务。
4. 两条路线都缺前置工具（`adb`、Node.js、Xcode）时，说明缺什么和怎么准备，不自行安装。

## 设备

- USB 调试和无线调试是同一条真机路线：连好后都只是 `adb devices` 中的一个序列号，后续用法相同。连接、配对和掉线处理见 [连接设备](./references/connect.md)。
- 开始操作前先列设备。有多台时明确指定一台并在汇报中写出；不默认使用第一台。
- 用户没有指定时，开发调试优先用模拟器；需要真机特有能力（相机、推送、性能、厂商系统差异）或用户指定时用真机。
- iOS 模拟器和 iOS 真机只能在 macOS 上使用（依赖 Xcode）；Windows 与 Linux 只能用 Android。
- 找不到设备时，引导用户连接本地设备或启动模拟器。mobile-mcp 在无设备时会提示改用云端设备，不跟随该提示；云端设备需要账号登录且按使用计费，只在用户主动要求时使用。

## 边界

真机通常是用户的私人手机，上面有真实账号、消息和隐私数据。

- **只读操作**（列设备、看界面元素、截图、读日志与崩溃、列出 App）在任务范围内可以直接做。
- **开发操作**：在模拟器上安装、启动、停止正在开发的 App 可以直接做；在真机上安装正在开发的 App 视为任务范围内操作，安装来源不明的安装包需先确认。
- **需要先说明影响并取得同意**：卸载 App、清除 App 数据、修改系统设置、修改定位或剪贴板、恢复出厂设置，以及任何波及其他 App 的操作。
- **对外写入**：在用户账号下发消息、发帖、下单、支付、改资料，需要用户对目标、动作和影响的明确授权；一般性的“帮我看看”不构成授权。
- **登录与身份**：登录、验证码、二次验证、指纹或面容验证交给用户在手机上完成；AI 不索要、不记录、不复述凭据。
- **隐私**：截图和元素树可能带有通知、聊天和个人信息。汇报只摘录与任务相关的部分；保存截图或录屏到项目目录前先确认，避免误提交到仓库。
- **视觉验收**：界面外观、动画和配色由用户在设备上验收。AI 可以检查非视觉项：是否崩溃、日志报错、元素是否存在、流程能否走通。
- 本 skill 不授予额外权限：安装软件、写入配置、联网和付费服务仍按宿主规则和用户授权执行。

## 汇报

说明使用的路线和设备（型号或序列号、真机或模拟器），做了哪些操作、哪些属于写入，以及用户需要在设备上亲自验证的内容。
